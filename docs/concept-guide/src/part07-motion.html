7.1 One Motion channel: distance

Today the animator keys offset_factor on every held constraint. Speed then depends on each curve's length, and a train crossing three curves has three unrelated F-curves. Instead, key one number per train: distance travelled, in metres.

Reversing is just a falling curve. A stop is a flat section. The route (Part 5) turns distance into curve and offset for every point of the train. Migration: the Convert operator (Part 5 §5.8) turns old offset keys into distance keys.

7.2 Timing tools

Speed Profile generator

Enter start frame, cruise speed (km/h or mph), acceleration and braking rates, and a stop distance or target marker. The operator writes distance keys with correct easing. It works for “depart the platform” shots.

Arrive At

Pick a target (a marker Empty on the track, a platform end, or another train's coupler). The operator computes the distance along the route to it and keys the train to stop exactly there on a chosen frame. It also handles coupling moves (stop with the couplers touching).

7.4 Wheel modes

A wheel of radius r rolling a distance s without slipping turns by θ = s ÷ r radians. Each wheel group has its own diameter: a 2-4-2's drivers turn much more slowly than its truck wheels.

ModeRotation =Use for
AUTOfacing × d_point / r from a driverNormal running. Zero effort, always in sync.
DIRECTThe animator's own keys (driver muted)Full manual control of a wheel set.
AUTO + SLIPfacing × d / r + slip_angle, where slip_angle is a keyable bone propertyWheel slip on starting (drivers spin, loco barely moves). Key slip_angle rising fast while distance creeps.
AUTO × GRIPgrip × (facing × d / r) + slip_angle, with grip 0–1Sliding or skidding under braking: grip → 0 locks the wheels while the train keeps moving.

#   d    = rig["ti_distance"]        written each frame by the pipeline (point distance)
#   r    = rig["ti_r_drivers"]       from the Vehicle Definition
#   g    = pose.bones["WHL_D1_L"]["grip"]         default 1.0 (keyable)
#   slip = pose.bones["WHL_D1_L"]["slip_angle"]   default 0.0 (keyable)
expression:  g * d / r + slip

Drivers are evaluated by Blender itself, so wheels also turn in background renders. Only the ti_distance value comes from Python, and a bake makes even that static (§7.8).

7.5 Secondary motion

These are all additive transforms on dedicated rig bones (“FX” bones under the body and bogies). They never feed back into the mechanism, and each has a master amount you can key to 0.

7.6 Speed readout

The Drive box shows live speed (km/h or mph), distance, the current segment, and next junction in N m. It helps with matching real timetables and with hitting marks. A small viewport overlay (the same safe draw-handler technique as the existing HUD) can show it on-screen while scrubbing.

7.7 Render-safe evaluation

The current risk

Pivots, wagons and held offsets only update for the active object. Render an animation with nothing (or the camera) selected, and every pivot and wagon stays wherever it was last left, while the root alone follows its keys. This is audit issue #1, and it should be fixed before any production use.

  1. Evaluate all consists

    In frame_change_pre, loop over scene.track_it_consists (not the selection) and run steps 1–4 of the pipeline (Part 3, Fig. 3.3).

  2. Mark the handler @persistent

    That is already the case. Re-register on load_post, and rebuild caches.

  3. Keep the rest native

    Constraints and drivers only after step 4, so the depsgraph evaluates everything in one pass.

  4. Test headless

    blender -b scene.blend -f 120 must produce the same pose as the viewport at frame 120 (Part 11 test plan).

7.8 Bake Train Motion

For render farms, exports (FBX/Alembic/USD to game engines) or sharing a file with someone who doesn't have the add-on:

  • Bake: for a frame range, evaluate each frame and key every managed constraint's offset_factor and influence (CONSTANT on influence), plus ti_distance on rigs. Tag the result ti_baked = True.
  • While baked, the pipeline skips that consist. Playback is pure keyframes.
  • Clear Bake: remove those keys and return to live evaluation.
  • Optional Bake to Transforms: visual_transform_apply per frame, for export to engines without Follow Path.
