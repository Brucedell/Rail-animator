1.3 How the current code is wired

The add-on is one 3,143-line file. It has three kinds of moving parts: operators the user clicks, handlers Blender calls on every update or frame change, and data stored on objects and the scene. The handlers do most of the work.

1.4 Handoff v8 vs the latest source

Reconciling the two sources
  • The latest source goes beyond handoff v8. It contains a full consist prototype: wagons, TrackIt_ConsistHistoryEntry, a cumulative route-distance odometer, _track_it_find_junction, _track_it_resolve_route_position, stale-history pruning, Fix Train, and the Consist Debug box. That is v8's Section 8.2/8.3 “theory” partly built for wagons, but not yet for pivots.
  • The Drag Pad prototype v8 describes (_track_it_draw_drag_pad, OT_DragPadGrab_Action) is not in this file. It is probably in the backed-up fork. Worth recovering before Phase 2 (Part 11).
  • bl_info still says version (1, 32) and Blender (3, 0, 0). The code uses the layered-Action API (action.layers → strips → channelbag), which only exists in recent Blender (the project runs 5.1). The minimum version should be raised so older Blenders refuse to load it cleanly.
  • A v9 handoff should record the consist work. This guide can stand in until then.

1.5 Code audit: issues found

Line numbers refer to the latest Track it compiled 1.py. Severity: High gives wrong results or breaks renders, Med is fragile or slow, Low is tidy-up.

#Sev.IssueWhy it matters / fix direction
1HighSyncing only happens for the active object. Both handlers start with view_layer.objects.active (L1171, L2361).Pivots, wagons and held-offset sync freeze whenever a different object is selected: during playback, during a render, or when a second train exists. Fix: evaluate every registered vehicle, not the selection (Part 7, render-safe evaluation).
2HighArc-table cache never invalidates. _track_it_switch_arc_cache is keyed by curve name and only cleared on unregister (L1036–1046, L3111).Edit, extend or move a curve after it has been used and every offset computed against it is silently wrong until the add-on reloads. Renaming a curve can also hit a stale entry. Fix: key by object pointer plus a hash of points, handles, tilt, matrix_world and resolution.
3HighPivots still clamp to the root's curve (L1731). The consist code already solved crossing for wagons but pivots don't use it.This is v8's §3.3 gap: a pivot past a curve end snaps to the boundary and the wheelbase breaks. Fix: pivots resolve through the same route resolver as wagons (Part 6).
4High?Wagons clone the root with root.copy() (L2554). Object-level collection properties (track_it_vehicle_pivots, track_it_consist_wagons, history) are ID properties and are very likely copied too.A wagon may inherit a wagon list that points at itself and the root's pivot Empties. If the wagon ever becomes active, the handler would sync that inherited list and fight the real root. Verify in Blender, then clear those collections on the clone.
5MedPer-tick cost grows with the scene. Job 2 scans every curve at 200 samples on every depsgraph update. closest_offset_factor is a 5,000-point brute-force loop.Fine for a test scene, slow on a real layout. Fix: a precomputed Track Network (Part 4) plus a spatial grid or KD-tree (mathutils.kdtree) per curve.
6MedHandlers write RNA inside depsgraph_update_post.Every write triggers another update pass. Guards (skip if unchanged) keep this finite, but it is a feedback loop. Prefer frame_change_pre for animation-driven work and do UI-driven work in the operator or callback itself.
7MedTwo history systems. Keyframe mining (_find_recorded_switch_point) for the root, and the odometer log for wagons.They can disagree. Keyframe mining was already contaminated twice by leftover test keys, and the odometer needs drift heuristics (replace_pair, DEDUP_EPS). Fix: one Route Plan (Part 5).
8MedIdentity by name strings. Ready sets store curve.name, markers encode obj.name, constraints are named FollowPath_{curve}.Renaming a vehicle orphans its switch markers, and renaming a curve breaks constraint lookup names. Fix: a stable UUID custom property on every managed object; match by pointer.
9Medbuild_arc_table ignores cyclic splines and spreads samples evenly per segment regardless of segment length.Closed loops (roundy-round layouts) are missing the closing segment. Long segments get fewer samples per metre. Fix: sample the evaluated curve (depsgraph polyline Blender itself follows) including the cyclic segment.
10MedPython-only state isn't undo-aware (ready sets, caches).After Ctrl+Z the Switching panel can show stale candidates until the next move. Fix: rebuild on undo_post / load_post.
11LowThe Drag Slider registers a new timer on every update (L473).Harmless but wasteful. Check bpy.app.timers.is_registered first.
12LowMute/enabled writes still sprinkled through the code after the influence migration.Add a one-time “Migrate constraints” operator, then delete the dual-state code.
13Low“Track It” / “Bank It” operators generate legacy shrinkwrap planes with bpy.ops chains.Nothing in the new architecture needs them. Replace with a Track Builder (Part 4).
14LowSingle file, globals, no tests.Split into a package (Part 3 §3.5) and add headless Blender tests (Part 11).

1.6 What “finished” means

Pulling the goals from every session together, the add-on is complete when an artist can:

  1. Build or import track quickly, with banking and switches, and have the add-on understand how the pieces connect.
  2. Turn any model into a vehicle (mine cart, subway car, 2-4-2 steam locomotive) through a guided set-up, and save it to a library.
  3. Couple vehicles into a train, drag it anywhere including backwards through switches, and have every car and every bogie stay on the correct rails.
  4. Animate it with ordinary keyframes and easing, with wheels, rods and secondary motion following automatically, or take manual control of any wheel for slip or slide.
  5. Render it reliably, on a farm or in the background, and get the same result every time.

The rest of this guide is the plan for getting there.
