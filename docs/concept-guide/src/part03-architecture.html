3.1 Design principles

Every principle below comes from a decision already made during the sessions. They are written down here so new code can be checked against them.

PrincipleIn practice
The mesh is never bolted to the mechanismThe add-on moves roots and pivots. The rig reads them through constraints, and meshes parent to the rig. Swap a mesh, keep the rig. Swap a rig, keep the mechanism.
Blender does the geometryWherever possible the add-on only sets numbers (offset_factor, influence, distance) and lets Follow Path, Copy Transforms and Damped Track do the maths. It is inspectable, keyframeable, and banking comes for free.
Distance is the currencyPivot offsets, coupling gaps, wheel rotation and route history are all real metres. Factors are only ever computed at the last moment, per curve.
Crash-safe live controlNo constraint writes from handlers during a modal 3D transform. Live control goes through N-panel widgets (Drag Slider, Drag Pad) or the add-on's own modal operators.
Deterministic playbackThe same frame must give the same pose no matter what is selected, whether you scrub forwards or backwards, or whether it's the viewport or a render farm.
No guessing at forksCurves change only where a decision was recorded or the continuation is unique. Proximity alone never switches a train (the lesson of v8 §4.2).
Everything reversibleDetach keeps constraints, Remove Switch confirms with real counts, and every operator is undoable.

3.3 Data model

Six types cover the whole system. Blender-side they are PropertyGroups on the scene or on objects, plus a few managed objects. Each carries a stable uid string, so renames never break links (audit issue #8).

The key simplification

Today each vehicle keeps its own history of where it went. In the target model the train's route is recomputed from two things: where it started, and what the turnouts were set to at each frame. Anything along the train (root, pivot, wagon, tender bogie) is then “the route at distance d − offset”. There is no history to go stale, no drift, and no per-wagon fork decisions. Part 5 explains the idea in full; Part 8 applies it to consists.

3.4 Per-frame evaluation pipeline

Render farms

Handlers are Python, and some render setups run with scripts disabled (“Auto Run Python Scripts” off) or on machines without the add-on. The pipeline should offer Bake Train Motion: write the resolved offset_factor and influence keys for every managed object over a frame range, so the scene plays back with the add-on turned off. See Part 7 §7.8.

3.5 Package layout

Blender loads a folder with __init__.py as one add-on (or as an Extension, the Blender 4.2+ format with blender_manifest.toml). Splitting by layer keeps each file small and testable:

track_it/
  blender_manifest.toml      # extension metadata (replaces bl_info), min Blender 4.4 / 5.x
  __init__.py                # register()/unregister() only
  core/
    arc.py                   # arc tables from the evaluated polyline, cache keyed by (uid, geo_hash)
    spatial.py               # KD-tree per segment, nearest point/offset queries
    network.py               # TrackNetwork scan: joints, overlaps, turnouts, validation
    route.py                 # RoutePlan walk, distance → (segment, factor, heading)
  mechanism/
    vehicle.py               # root, pivots, facing, constraint management by uid
    consist.py               # members, gaps, coupling, anchor
    evaluate.py              # evaluate_all(): the per-frame pipeline (steps 1–4)
    bake.py                  # Bake Train Motion / Clear Bake
  rig/
    wheels.py                # Auto/Direct/Slip drivers, radius per group
    secondary.py             # sway, hunting, suspension, rail-joint bumps
    bind.py                  # connect rig bones to pivots (Copy Transforms etc.)
  assets/
    vehicle_def.py           # VehicleDef read/write, asset metadata
    wizard.py                # “Make Vehicle” guided setup (Part 9)
  drive/
    slider.py  pad.py        # live controls (Drag Pad = crash-safe mouse drive)
  ui/
    panels.py  lists.py  hud.py  overlays.py
  ops/                       # thin operators that call into the modules above
  handlers.py                # frame_change_pre, load_post, undo_post (rebuild caches)
  tests/                     # headless tests: blender -b -P tests/run.py

3.6 Where state lives

StateStored inNotes
Track Network, JunctionsScene PropertyGroupSaved in the .blend. Rebuilt on demand, or flagged dirty on geometry change.
Junction stateIntProperty (keyframeable)Constant-interpolation F-curve, which is the switch history. Visible in the Dope Sheet.
Consist distanceFloatProperty (keyframeable)The one Motion channel. Ease it in the Graph Editor to get acceleration and braking.
Vehicle / pivot / member dataObject PropertyGroupsAs today, plus uid. Clear these on duplicate (audit #4).
Follow Path constraintsOn managed objectsOutputs of the pipeline. Keyframes on them only appear after a Bake.
Arc tables, KD-trees, route spansPython cacheRebuilt on load_post / undo_post / hash change. Never trusted blindly.
HUD message, live-drag timingPython module globalsUI-only, safe to lose.

3.7 Architecture decisions

DecisionRecommendationTrade-off
Keep Follow Path, or position Empties directly?Keep Follow Path. It gives banking, is inspectable and bakeable, and matches Blender's own curve sampling.One constraint per curve per object, managed by uid (that is already the model).
Motion channel: keyed offset_factor or keyed distance?Keyed distance on the Consist (Part 7). Offsets become outputs.Existing keyframed scenes need a one-time migration operator.
History: keyframe mining, odometer log, or Route Plan?Route Plan: start point + keyframed junction states.Replaces a lot of working code, so do it in Phase 3, after the Track Network exists.
Evaluate only the active object, or everything?Everything, every frame, in frame_change_pre.Needs the caching work (arc tables, KD-trees) to stay fast.
Single file or package?Package / Extension.Installation changes from a .py file to a .zip, one time.
Rig: armature per vehicle, or Empties only?Armature per vehicle (Part 6): bones are what animators expect.A mine cart can use a tiny 3-bone rig. The system doesn't need a complex rig.
